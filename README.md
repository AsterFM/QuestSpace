# QuestSpace

Текстовые квесты в формате переписки. Игрок отвечает на сообщения персонажа, а автор связывает диалоги и развилки на карте истории в браузере.

Это локальный прототип: один автор, каталог опубликованных историй, редактор и мобильный клиент. Учётных записей, разграничения доступа и Supabase пока нет. API редактора рассчитан на локальную разработку; перед публичным размещением нужны авторизация и проверка владельца истории.

## Быстрый запуск

Нужны Node.js 24 и npm. Используйте существующий checkout — облачная задача уже изолирована, дополнительный Git worktree не нужен.

```sh
cd /workspace/QuestSpace
npm ci
npm run dev
```

Команда запускает API на порту 3001 и браузерный клиент на порту 5173. Оба слушают только loopback по умолчанию. В каталоге сразу есть история «Последний сигнал» с тремя концовками. В браузере доступны каталог, прохождение и авторская мастерская. В облачном onboarding ссылки предпросмотра не поддерживаются; проверяйте сервисы локальными запросами и тестами.

В другом терминале выполните `npm run smoke`: проверка дождётся сервисов и проверит каталог, опубликованную историю, доступную концовку, мастерскую и веб-клиент.

Данные хранятся в `.data/questspace.sqlite` и переживают перезапуск. Не удаляйте эту папку для обновления приложения. Сервер создаёт демонстрационную историю только при её отсутствии. Параметры API: `HOST`, `PORT`, `DATA_DIR`, `CORS_ORIGINS` (точные разрешённые origin через запятую).

## Редактор

1. Откройте «Мои истории» и создайте историю.
2. В «Об истории» задайте название, описание, автора и имя персонажа.
3. Выберите блок на карте и измените сообщения и ответы в правой панели.
4. Добавьте блоки. Потяните стрелку от точки у ответа к точке слева следующего блока. Можно также выбрать следующий блок в выпадающем списке.
5. Отметьте концовки как финалы. Стартовый блок можно выбрать в панели; его нельзя удалить, пока он остаётся стартовым.
6. Предпросмотр открывает настоящий чат с текущим черновиком. «Сохранить» сохраняет черновик, «Опубликовать» проверяет граф и обновляет отдельную версию для игроков.

При публикации проверяются заполненные тексты, уникальные идентификаторы, все переходы, достижимость блоков и возможность выйти в финал из каждой ветки. Циклы с выходом разрешены. Пустые сообщения и ответы не сохраняются; незаконченные соединения разрешены в черновике. Лимиты: 300 блоков, 30 сообщений в блоке, 6 ответов, 1 МБ на API-запрос.

Несохранённые правки защищены предупреждением при выходе, но не восстанавливаются после закрытия вкладки: сохраняйте черновик кнопкой. Две вкладки не могут незаметно перезаписать друг друга — API проверяет номер версии.

## Мобильное приложение

```sh
# Из корня проекта, API должен работать отдельно.
npm run dev:mobile
```

Клиент Expo показывает каталог опубликованных квестов и переписку. Реплики персонажа появляются последовательно; ответы доступны после окончания сообщений. Прогресс хранится на устройстве через AsyncStorage. Браузерное прохождение хранит прогресс в localStorage. Синхронизации между устройствами пока нет. Повторная публикация изменённой истории сбрасывает несовместимый прогресс; прохождение уже открытой истории продолжается на загруженной версии.

Адрес API задаётся через `EXPO_PUBLIC_API_URL`, пример находится в `apps/mobile/.env.example`. Это публичный адрес сервера, не секрет.

- Web/iOS Simulator на той же машине: `http://127.0.0.1:3001`.
- Android Emulator: `http://10.0.2.2:3001`.
- Физический телефон: LAN-адрес машины с API. Явно задайте `HOST` на этот интерфейс при запуске API; `localhost` на телефоне означает сам телефон. Если используете браузерный клиент с другим origin, добавьте его в `CORS_ORIGINS`.

В Linux без Android SDK и macOS можно проверить Metro/Hermes-сборку для обеих платформ, но для установки и запуска нативного приложения нужны устройство с совместимым Expo Go либо соответствующая нативная среда сборки. Облачная среда не предоставляет пользовательский QR/localhost-предпросмотр.

Веб-версия именно мобильного клиента для внутренней проверки:

```sh
CI=1 EXPO_NO_TELEMETRY=1 EXPO_OFFLINE=1 npm run web -w @questspace/mobile -- --localhost
```

Она запускается на порту 8081. Режим offline отключает внешние обращения CLI Expo; запросы приложения к локальному API работают.

## Проверки

```sh
npm run typecheck
npm test
npm run build
CI=1 EXPO_NO_TELEMETRY=1 EXPO_OFFLINE=1 npm exec -w @questspace/mobile -- expo export --platform all --max-workers 2
npm run test:e2e
```

`npm test` проверяет развилки, восстановление истории, валидацию публикации, конфликты сохранения и устойчивость SQLite к перезапуску. E2E запускает отдельные API/веб-сервисы с временной базой; проверяет игрока, автора и мобильную ширину экрана. Остановите собственный `npm run dev` перед E2E, поскольку тесты используют те же порты.

E2E использует системный `/usr/bin/chromium`, если он есть, либо браузер Playwright. Другой системный Chromium можно задать через `PLAYWRIGHT_CHROMIUM_PATH`. На машине без браузера выполните `npx playwright install chromium` (и установите необходимые системные библиотеки). Загрузка Playwright требует доступа к доменам его CDN; в данной облачной среде достаточно предустановленного Chromium.

## Структура

- `apps/web` — React, Vite и React Flow: каталог, чат, карта диалогов.
- `apps/mobile` — React Native и Expo SDK 57: каталог и чат для Android/iOS/web.
- `apps/api` — Express и встроенный в Node.js SQLite: черновики и опубликованные снимки.
- `packages/story` — общая схема Zod, валидация графа и проигрыватель истории.
- `tests` — браузерные сценарии Playwright.

Для установки нужны публичные пакеты из `registry.npmjs.org`, внешние ключи не требуются. По умолчанию npm-кеш хранится в игнорируемой `.cache/npm`. В облаке установочный скрипт использует общий кеш `/workspace/.npm-cache`.

Следующий этап продукта — аккаунты авторов, права доступа и общее серверное хранилище (например, Supabase). Затем можно добавить условия выбора, персонажей, изображения и синхронизацию прогресса.
